기능 목록으로 보면 상당히 구현됐습니다. 그러나 AJD의 기준으로 보면 현재는 **“작동하는 연구 워크벤치”**이고, 아직 **“신뢰 가능한 도메인 전문 연구위원”**까지는 한 단계 남았습니다.

| AJD 책임      | 현재 상태                                | 남은 핵심 공백                                               |
| ----------- | ------------------------------------ | ------------------------------------------------------ |
| 문헌·노트 지식화   | PDF/탐색→후보 카드→승인 흐름 구현                | 카드 근거의 페이지·섹션·DOI·정확 발췌가 항상 채워지지는 않음                   |
| 지식 관계·계보    | 관계 승인, SQLite 관계 테이블, 계보·경로 탐색 구현    | M2가 다단계 경로를 실제 보고·자문에 사용하는 폐루프는 아직 약함                  |
| 비판적 연구 검토   | 지지/반대/숨은 가정/한계 프롬프트와 M2 보고 구현        | 이 항목들의 누락을 코드가 검증하지 않음. LLM이 빼먹어도 보고서가 저장될 수 있음        |
| 연구 공백→후속 탐색 | Intent 승인→탐색→P1 후보 흐름 구현             | 공백·재검증·주장 검증은 프롬프트 자산 중심이며, 독립된 운영 화면·상태 전이는 미완성       |
| 외부 자문       | 요청 해석과 답변 초안 흐름 존재                   | 요청자 확인→범위 확정→답변 발송→종결의 상태 관리와 내부 보고 분리가 미완성            |
| 운영·감사       | 승인 원장, LLM 호출 로그, 탐색 로그, Delta 요약 구현 | 재시도·중단 후 재개·중복 방지·실행 결과 검증이 아직 시스템 수준으로 완결되지 않음        |
| 성과 평가       | 일부 로그와 Delta 존재                      | 출처 정확도, 관계 오류, 반대 근거 검토율, 탐색 대비 승인률 같은 AJD KPI 대시보드 부재 |

가장 중요한 부족분은 세 가지입니다.

1. 근거 품질 게이트

현재는 승인된 카드라도 `source_document_only`, 빈 발췌, 불완전한 페이지 정보가 가능할 수 있습니다. AJD의 “출처 정확도 100%”를 만족하려면 카드마다 최소한 다음 상태를 분리해야 합니다.

* `candidate`: 후보
* `approved_unverified`: 연구자 승인했지만 정확 위치 미확인
* `verified`: 원문·페이지·섹션·발췌가 확인됨
* `superseded` 또는 `retracted`: 후속 근거로 약화·대체됨

특히 M2가 강한 결론을 낼 때는 `verified` 카드만 근거로 쓰게 해야 합니다. 이것이 현재 시스템의 신뢰도를 가장 크게 올릴 작업입니다.

2. M2 비판 검토의 구조화·검증

프롬프트에는 반대 근거·숨은 가정·조건·한계를 요구하고 있습니다. 좋습니다. 다만 결과가 자유 형식 Markdown이라, 실제로는 빈 섹션이나 근거 없는 해석도 저장될 수 있습니다.

M2 보고서를 다음처럼 구조화해 검증하는 단계가 필요합니다.

* `evidence_card_ids`
* `supporting_evidence`
* `counter_evidence`
* `hidden_assumptions`
* `conditions`
* `knowledge_gaps`
* `recommended_decision`

그리고 `counter_evidence`가 없으면 “관련 승인 지식에서 반대 근거를 찾지 못함”이라고 명시하게 해야 합니다. “반대 근거를 검토했다”와 “반대 근거가 없다”를 구분할 수 있어야 합니다.

3. 탐색·검증 작업의 운영화

현재 100편→5편→3편 흐름은 잘 잡혔지만, 아직 긴 작업을 Streamlit 실행과 야간 스크립트가 직접 맡는 형태입니다. 따라서 다음이 필요합니다.

* 작업 단위 상태: `queued / running / retryable_failed / completed / cancelled`
* 단계별 재개: 검색은 끝났는데 PDF 3/5에서 실패한 경우
* 동일 Intent·동일 검색 계획의 중복 실행 방지
* PDF 추출 실패, LLM timeout, 형식 오류를 분리한 재시도 정책
* 완료 후 큐 제외와 실행 로그 보존의 일관성

이 세 가지가 잡히면 “데모 기능”에서 “매일 써도 되는 연구 운영 도구”로 바뀝니다.

그 다음 우선순위는 외부 자문입니다. AJD상 외부 자문은 부가 기능이 아니라, M2가 내부 연구 축적을 다른 전문성·질문자와 만나는 방식으로 시험하는 중요한 시나리오입니다. 다만 지금은 내부 연구 루프의 근거 품질이 더 먼저입니다.

정리하면, 새 기능을 더 많이 추가할 시점은 아닙니다. 다음 스프린트는 **근거 검증 상태 → 구조화된 M2 비판 보고 → 장기 작업 안정화**에 집중하는 것이 맞습니다. 그 뒤에 외부 자문 종결 흐름과 KPI 대시보드를 붙이면 AJD의 핵심 책임이 거의 닫힙니다.


---



다음 단계는 기능을 더 늘리기보다, 지금 만든 순환을 **신뢰 가능한 연구 운영 체계**로 만드는 일입니다. 우선순위는 아래가 적절합니다.

1. 탐색 파이프라인 안정화

* arXiv 호출·PDF 다운로드·본문 추출·LLM 단계별 상태와 오류 원인 기록
* 오래 걸리는 작업을 화면 실행과 분리한 작업 큐/백그라운드 워커
* 재시도·중단 후 재개·중복 실행 방지
* 100편→5편→3편의 선정 근거와 각 프롬프트 결과를 실행 로그에서 재현 가능하게 보존

2. P1 카드의 근거 품질 강화

* 카드마다 논문명뿐 아니라 페이지·섹션·근거 발췌·DOI를 필수화
* 본문 주장, 저자의 한계, 연구위원의 해석을 분리
* 동일 논문/유사 주장 중복 탐지
* 승인 전 카드 묶음을 비교·병합·반려하는 검토 UI

3. P2를 실제 지식 그래프로 고도화

* 현재 카드 간 관계 후보를 인용, 확장, 반박, 보완, 조건부 적용 등으로 정교화
* 관계마다 양방향 근거와 조건을 저장
* 특정 연구질문에 대해 다단계 경로를 찾아 “이 결론이 어떤 논문·관계를 거쳐 나왔는지” 제시
* RDF/JSON 형태의 Knowledge Graph Delta 내보내기

4. M2 비판적 연구 검토 강화

* 매 연구질문마다 지지 근거뿐 아니라 반대 근거를 최소 1개 이상 검토
* 신규성, 숨은 가정, 논리 공백, 적용 조건을 별도 항목으로 고정
* 관련 질문들을 연구주제 포트폴리오로 묶어 가설·진척·미결 사항·후속 Intent를 관리
* M1 탐색 결과가 들어오면 해당 질문의 연구상태를 갱신하도록 연결

5. 활동 의미 요약의 실용화

* 밤 12시 Delta 요약이 단순 활동 나열이 아니라 “새로 강화된 주장 / 약화된 가설 / 새 공백 / 다음 판단”을 제시
* 연구주제별 주간·월간 보고서
* 요약에 사용된 카드·보고서·Intent로 바로 이동하는 근거 링크

6. 운영·평가 체계

* 출처 정확도, 카드 중복률, 관계 오류, 탐색 대비 승인률, 발견된 공백 수를 대시보드화
* 연구자 수정·반려를 다음 카드·관계·Intent 생성에 반영하는 피드백 규칙
* 데이터 백업·내보내기·복구 및 프로젝트별 지식 분리

제가 보기에는 다음 구현은 **1번 작업 큐·실행 로그 안정화**가 가장 먼저입니다. 지금의 arXiv/PDF/LLM 흐름은 유용하지만 길고 타임아웃 가능성이 있으므로, 이것이 안정돼야 P2·M2의 품질 개선도 실제 연구 습관으로 정착합니다.
